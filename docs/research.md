# Investigación y Proceso UX/UI - Portfolio Web Personal

## 1. Definición del Usuario Objetivo (Proto-Persona & Escenario)

### Proto-Persona
* **Nombre:** Valeria Ramos
* **Rol:** Tech Recruiter / UX Team Lead en empresa de software.
* **Objetivo:** Encontrar desarrolladores Frontend / Full-Stack con bases sólidas en ingeniería de software, código limpio y capacidad para resolver problemas mediante casos de estudio.
* **Necesidad clave:** Evaluar en menos de 30 segundos si el candidato maneja buenas prácticas, tecnologías modernas y proyectos funcionales desplegados.

### Escenario de Uso
Valeria recibe decenas de portfolios al día. Abre el sitio desde su celular o laptop, revisa el Hero y las métricas principales, y salta inmediatamente a la sección de Proyectos para probar una demo en vivo y leer la arquitectura detrás del proyecto principal.

## 2. Benchmark de Referencia (Análisis de 3 Portfolios)

1. **Portfolio 1: Perfil Minimalista de Desarrollador (Referencia Estilo Tech)**
   * **Qué funciona:** 
     * Navegación por anclas extremadamente fluida y limpia.
     * Uso de tipografías de alta legibilidad y jerarquía visual clara.
     * Acceso rápido a repositorios de código y links directos.
   * **Qué no funciona:** 
     * Carece de casos de estudio profundos; presenta los proyectos únicamente como tarjetas con enlaces breves.
     * El contraste en algunos textos secundarios es bajo, afectando la accesibilidad.

2. **Portfolio 2: Enfoque Centrado en UX/UI y Casos de Estudio (Referencia Metodológica)**
   * **Qué funciona:** 
     * Estructura impecable basada en la metodología de resolución de problemas (Problema, Solución y Resultado).
     * Excelente distribución de métricas y *highlights* al inicio de la página.
   * **Qué no funciona:** 
     * Animaciones excesivas al hacer *scroll* que ralentizan la carga y pueden marear al usuario.
     * Estructura de código sobrecargada con frameworks innecesarios para un sitio que debería ser estático.

3. **Portfolio 3: Portfolio Académico / Institucional (Referencia Base)**
   * **Qué funciona:** 
     * Línea de tiempo de formación y experiencia muy clara y ordenada.
     * Uso correcto de *tags* de tecnologías visibles en cada sección.
   * **Qué no funciona:** 
     * Diseño visual demasiado genérico y clonado de plantillas prearmadas sin identidad propia.
     * Falta de adaptabilidad (*responsive*) óptima en dispositivos móviles pequeños (se rompe el menú hamburguesa).

## 3. Marca Personal y Concepto Visual

* **Palabras Clave de Marca:**
  1. *Metódico:* Estructura clara, código limpio y arquitectura ordenada.
  2. *Escalable:* Componentes modulares, persistencia de datos y desarrollo pensado a futuro.
  3. *Funcional:* Enfoque en resolver problemas reales con interfaces intuitivas y veloces.

* **Traducción Visual:**
  * **Estilo:** Tech / Moderno.
  * **Paleta de Colores:** Primario Índigo (`#4F46E5`), Secundario Esmeralda (`#10B981`), Texto Pizarra (`#1E293B`), Fondo Gris Claro (`#F8FAFC`).
  * **Tipografía:** Inter (palo seco moderna, limpia y altamente legible).

## 4. Estructura de Proyectos Selección

1. **FixApp (Caso de Estudio Principal):**
   * *Tipo:* Aplicación Web Full-Stack de gestión de reclamos.
   * *Despliegue:* Vercel + Base de Datos activa.
   * *Enfoque:* Desglose completo de Problema, Solución, Arquitectura y Aprendizajes.

2. **Cubrí (Proyecto Secundario):**
   * *Tipo:* Cotizador de seguros digitales de celulares.
   * *Enfoque:* Navegación SPA, manejo de estado (`localStorage`) y cálculo de cuotas dinámico.

3. **Rick & Morty App (Proyecto Secundario):**
   * *Tipo:* Web App interactiva.
   * *Enfoque:* Consumo de API REST, renderizado dinámico y filtrado de personajes.
